# LAIM Extract Sample

Детерминированное сэмплирование UMR перед LLM-ассесором.

## Назначение

Нода ставится между **конвертером трейсов** (выход `monitoring_umr`) и **LAIM Asessor Agent** (вход `monitoring_umr`):

```
Конвертер → [monitoring_umr] → Extract Sample → [monitoring_umr_sample] → Asessor Agent
```

Отбирает заданное число целых единиц: сессий либо отдельных строк. Схему и содержимое строк не меняет. Длина сессии не влияет на включение.

## Параметры оператора

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|---------------|----------|
| `sample_size` | int | 1000 | Максимум единиц отбора: сессий при packed/whole_sessions=true, строк иначе. 0 = все |
| `seed` | int | 42 | Зерно детерминированного отбора. Фиксирует порядок выборки |
| `whole_sessions` | bool | true | Если true — сессии отбираются целиком (диалог не режется). Если false — можно брать отдельные строки внутри сессии |

## Формат входных данных

Нода работает с двумя форматами UMR:

### Packed-форма (колонка `dialogue`)
```
session_id | dialogue
-----------+------------------------------------------
s1         | [[q1, в1, о1], [q2, в2, о2], ...]   ← список turns
```
- Строка = сессия целиком
- Пример = один turn из списка `dialogue`
- `whole_sessions=true` всегда значит целые строки (сессии), т.к. диалог уже упакован

### Плоская форма (колонка `query_id`)
```
query_id | input_query | output_answer | session_id | reference_group_id
---------+-------------+---------------+------------+------------------
s1-t1    | вопрос      | ответ         | s1         | g1
s1-t2    | вопрос      | ответ         | s1         | g1
```
- Строка = один turn
- Пример = строка датафрейма
- При `whole_sessions=true` берутся целые сессии (группировка по `session_id` / `reference_group_id`)

## Логика отбора

Отбор **равномерный и воспроизводимый**:

1. Входные данные разбиваются на единицы отбора (сессии или строки)
2. Каждая единица получает хеш `sha256(f"{seed}:{ключ_сессии}")`
3. Единицы сортируются по хешу (возрастание)
4. Берутся первые `min(sample_size, population_units)` единиц целиком; 0 означает все
5. Размер диалога влияет на число переданных turns, но не на решение о включении

Состав выбранных единиц не зависит от порядка входных строк при устойчивых уникальных ключах и одинаковом `seed`. Порядок строк внутри выбранных единиц сохраняется. Пустые и неоднозначные ключи отклоняются.

## Обработка краевых случаев

| Ситуация | Поведение |
|----------|-----------|
| `sample_size = 0` | Все примеры передаются без изменений |
| Единиц отбора на входе ≤ `sample_size` | Выборка передаётся целиком |
| Пустой DataFrame | Возвращается пустой DataFrame |
| Длинная сессия | Отбирается наравне с короткой, без обрезания |
| Нет `dialogue` и нет `query_id` | Ошибка с описанием ожидаемых колонок |

## Выходной порт

| Порт | Тип | Описание |
|------|-----|----------|
| `monitoring_umr_sample` | dataframe | Не более `sample_size` единиц отбора; число turns не ограничено. Подключается ко входу `monitoring_umr` ассесора |
| `sample_meta` | default (JSON) | Провенанс выборки: `unit` (`packed_dialogue` / `session` / `row`), `population_units`, `population_examples`, `sampled_units`, `sampled_examples`, `fraction`, `design`, `inclusion_probability`, `sample_size`, `seed`, `whole_sessions`, `passthrough`. Подключается ко входу `sample_meta` агрегатора |

## Статистический смысл и ресурсные ограничения

`design=hash_srs_units_v1` обозначает отбор фиксированного числа единиц по
псевдослучайному хеш-рангу. `inclusion_probability=k/G` относится к единице
отбора и всем её turns; для пустой совокупности значение `null`.
`fraction` — фактическая доля переданных turns, она не равна вероятности
включения при разных длинах сессий. При фиксированном seed отбор детерминирован;
проверки равномерности проводятся по разным seeds.

В `whole_sessions=true` это кластерная выборка. Turn-level среднее является
отношением сумм по отобранным группам; обычный интервал по независимым turns
не становится корректным благодаря этой ноде. Для него требуется учёт групп
и дизайна в статистической ноде. В `turn_with_history` обязательно сохранять
целые сессии: `whole_sessions=false` может удалить необходимую историю.

`sample_size` больше не является лимитом turns. Ограничивать память/токены
нужно на исполнении с сохранением всех выбранных исходов; пропуск тяжёлых
сессий возвращает смещение. При подготовке ranked выборки используются
`heapq.nsmallest` (O(G log k)) и хранимые позиции исходного DataFrame; чтение
всего UMR остаётся ограничением памяти, потоковое чтение здесь не реализовано.

## Примеры

```python
import pandas as pd
from main import main

# Плоский UMR: 4 сессии по 2-4 примера
frame = pd.DataFrame([
    {"query_id": "s1-t1", "input_query": "в1", "output_answer": "о1", "session_id": "s1"},
    {"query_id": "s1-t2", "input_query": "в2", "output_answer": "о2", "session_id": "s1"},
    # ...
])

# Sample: до 5 сессий целиком
result = main(monitoring_umr=frame, sample_size=5, seed=42, whole_sessions=True)
# Длина каждой выбранной сессии произвольна; все её turns сохраняются

# Sample: до 5 примеров, отдельные строки
result = main(monitoring_umr=frame, sample_size=5, seed=42, whole_sessions=False)
# Строки набираются по хешу, пока не наберётся 5
```
